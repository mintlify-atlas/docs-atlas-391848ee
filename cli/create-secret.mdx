title: "Create Kubernetes Secrets for Flux with the CLI"
sidebarTitle: "Create Secret"
description: "Use flux-operator create secret to create typed Kubernetes secrets for Git auth, OCI registries, SSH, SOPS decryption, TLS certificates, and Flux Web UI configuration."
---

The `flux-operator create secret` commands create Kubernetes `Secret` resources specifically shaped for Flux consumers — `GitRepository`, `OCIRepository`, `HelmRepository`, `Bucket`, and the Flux Web UI. Each sub-command validates required fields, formats the secret data according to the Flux API contract, and either applies it directly to the cluster or exports it in YAML format for GitOps workflows. All sub-commands support the same set of common flags for namespace, labels, annotations, and export mode.

## Common Flags

These flags are available on **every** `create secret` sub-command:

| Flag | Description |
|---|---|
| `-n, --namespace` | Namespace in which to create the secret |
| `--annotation` | Annotations to set on the resource (e.g. `annotation1=value1,annotation2=value2`) |
| `--label` | Labels to set on the resource (e.g. `label1=value1,label2=value2`) |
| `--immutable` | Set the `immutable` flag on the Secret |
| `--export` | Export the secret in YAML format to stdout instead of creating it in the cluster |

## basic-auth

Creates a Kubernetes Secret containing HTTP basic authentication credentials, used with `GitRepository` or `HelmRepository` sources backed by private repositories.

**Flags**

| Flag | Description |
|---|---|
| `--username` | Username for basic authentication **(required)** |
| `--password` | Password for basic authentication |
| `--password-stdin` | Read the password from stdin |

**Examples**

<Tabs>
  <Tab title="GitLab Token">
    ```shell
    echo $GITLAB_TOKEN | flux-operator create secret basic-auth flux-system \
      --namespace=flux-system \
      --username=git \
      --password-stdin
    ```
  </Tab>
  <Tab title="GitHub Token">
    ```shell
    flux-operator create secret basic-auth flux-system \
      --namespace=flux-system \
      --username=my-github-user \
      --password=$GITHUB_TOKEN
    ```
  </Tab>
  <Tab title="Export to YAML">
    ```shell
    echo $GIT_TOKEN | flux-operator create secret basic-auth flux-system \
      --namespace=flux-system \
      --username=git \
      --password-stdin \
      --export
    ```
  </Tab>
</Tabs>

**When to use:** Any private Git repository sync configured with `spec.sync.kind: GitRepository` and a `pullSecret` reference. The secret name must match the `pullSecret` field in the `FluxInstance`.

## githubapp

Creates a Kubernetes Secret containing GitHub App credentials for authenticating with GitHub repositories. Requires a registered GitHub App with the repository access permission.

**Flags**

| Flag | Description |
|---|---|
| `--app-id` | GitHub App ID **(required)** |
| `--app-installation-id` | GitHub App Installation ID **(required)** |
| `--app-private-key-file` | Path to the GitHub App private key `.pem` file **(required)** |
| `--app-base-url` | GitHub base URL for GitHub Enterprise Server (optional) |

**Examples**

<Tabs>
  <Tab title="GitHub.com">
    ```shell
    flux-operator create secret githubapp flux-system \
      --namespace=flux-system \
      --app-id=1 \
      --app-installation-owner=my-org \
      --app-private-key-file=./path/to/private-key-file.pem
    ```
  </Tab>
  <Tab title="GitHub Enterprise">
    ```shell
    flux-operator create secret githubapp flux-system \
      --namespace=flux-system \
      --app-id=42 \
      --app-installation-id=12345 \
      --app-private-key-file=./private-key.pem \
      --app-base-url=https://github.my-org.com
    ```
  </Tab>
  <Tab title="Export to YAML">
    ```shell
    flux-operator create secret githubapp flux-system \
      --namespace=flux-system \
      --app-id=1 \
      --app-installation-id=99 \
      --app-private-key-file=./private-key.pem \
      --export
    ```
  </Tab>
</Tabs>

**When to use:** `FluxInstance` sync configured with `spec.sync.provider: github`. GitHub App auth was introduced in Flux v2.5.0 and Flux Operator v0.16.0.

The corresponding `FluxInstance` sync configuration:

```yaml
spec:
  sync:
    kind: GitRepository
    provider: github
    url: "https://github.com/my-org/my-fleet.git"
    ref: "refs/heads/main"
    path: "clusters/my-cluster"
    pullSecret: "flux-system"
```

## proxy

Creates a Kubernetes Secret containing HTTP/S proxy credentials for Flux controllers that need to reach external services through a corporate proxy.

**Flags**

| Flag | Description |
|---|---|
| `--address` | Proxy address (e.g. `http://proxy.my-org.com:3128`) **(required)** |
| `--username` | Username for proxy authentication (optional) |
| `--password` | Password for proxy authentication (optional) |
| `--password-stdin` | Read the password from stdin |

**Examples**

```shell
# Unauthenticated proxy
flux-operator create secret proxy corp-proxy \
  --namespace=flux-system \
  --address=http://proxy.my-org.com:3128

# Authenticated proxy
echo $PROXY_PASSWORD | flux-operator create secret proxy corp-proxy \
  --namespace=flux-system \
  --address=http://proxy.my-org.com:3128 \
  --username=proxyuser \
  --password-stdin
```

## registry

Creates a Kubernetes `Secret` of type `kubernetes.io/dockerconfigjson` containing OCI registry credentials, used with `OCIRepository` sources or the Flux Operator distribution registry.

**Flags**

| Flag | Description |
|---|---|
| `--server` | Registry server hostname (e.g. `ghcr.io`) **(required)** |
| `--username` | Username for registry authentication **(required)** |
| `--password` | Password or token for authentication |
| `--password-stdin` | Read the password from stdin |

**Examples**

<Tabs>
  <Tab title="GHCR">
    ```shell
    echo $GITHUB_TOKEN | flux-operator create secret registry flux-system \
      --namespace=flux-system \
      --server=ghcr.io \
      --username=flux \
      --password-stdin
    ```
  </Tab>
  <Tab title="Docker Hub">
    ```shell
    flux-operator create secret registry dockerhub-creds \
      --namespace=apps \
      --server=registry-1.docker.io \
      --username=my-user \
      --password=$DOCKER_TOKEN
    ```
  </Tab>
  <Tab title="AWS ECR">
    ```shell
    echo $ECR_TOKEN | flux-operator create secret registry ecr-creds \
      --namespace=flux-system \
      --server=123456789.dkr.ecr.us-east-1.amazonaws.com \
      --username=AWS \
      --password-stdin
    ```
  </Tab>
  <Tab title="Export to YAML">
    ```shell
    echo $GITHUB_TOKEN | flux-operator create secret registry flux-system \
      --namespace=flux-system \
      --server=ghcr.io \
      --username=flux \
      --password-stdin \
      --export
    ```
  </Tab>
</Tabs>

**When to use:** `FluxInstance` sync with `spec.sync.kind: OCIRepository` pointing to a private container registry.

## sops

Creates a Kubernetes Secret containing SOPS decryption keys (Age or GPG private keys) used by the `kustomize-controller` to decrypt encrypted manifests.

**Flags**

| Flag | Description |
|---|---|
| `--age-key-file` | Path to Age private key file (repeatable) |
| `--gpg-key-file` | Path to GPG private key file (repeatable) |
| `--age-key-stdin` | Read Age private key from stdin |
| `--gpg-key-stdin` | Read GPG private key from stdin |

**Examples**

<Tabs>
  <Tab title="Age Key (file)">
    ```shell
    flux-operator create secret sops sops-age \
      --namespace=flux-system \
      --age-key-file=./age.agekey
    ```
  </Tab>
  <Tab title="Age Key (stdin)">
    ```shell
    cat age.agekey | flux-operator create secret sops sops-age \
      --namespace=flux-system \
      --age-key-stdin
    ```
  </Tab>
  <Tab title="GPG Key">
    ```shell
    flux-operator create secret sops sops-gpg \
      --namespace=flux-system \
      --gpg-key-file=./private.gpg
    ```
  </Tab>
  <Tab title="Multiple Keys">
    ```shell
    flux-operator create secret sops sops-keys \
      --namespace=flux-system \
      --age-key-file=./key1.agekey \
      --age-key-file=./key2.agekey
    ```
  </Tab>
</Tabs>

**When to use:** Any `Kustomization` that references encrypted files via `.spec.decryption.secretRef`. The secret must be in the same namespace as the `Kustomization`.

## ssh

Creates a Kubernetes Secret containing SSH credentials for authenticating with Git repositories over SSH.

**Flags**

| Flag | Description |
|---|---|
| `--private-key-file` | Path to SSH private key file **(required)** |
| `--public-key-file` | Path to SSH public key file (optional) |
| `--knownhosts-file` | Path to SSH `known_hosts` file **(required)** |
| `--password` | Password for an encrypted SSH private key (optional) |
| `--password-stdin` | Read the passphrase from stdin |

**Examples**

<Tabs>
  <Tab title="Basic SSH">
    ```shell
    flux-operator create secret ssh flux-system \
      --namespace=flux-system \
      --private-key-file=./id_rsa \
      --knownhosts-file=./known_hosts
    ```
  </Tab>
  <Tab title="Encrypted Private Key">
    ```shell
    echo $SSH_PASSPHRASE | flux-operator create secret ssh flux-system \
      --namespace=flux-system \
      --private-key-file=./id_rsa_encrypted \
      --knownhosts-file=./known_hosts \
      --password-stdin
    ```
  </Tab>
  <Tab title="With Public Key">
    ```shell
    flux-operator create secret ssh flux-system \
      --namespace=flux-system \
      --private-key-file=./id_ed25519 \
      --public-key-file=./id_ed25519.pub \
      --knownhosts-file=./known_hosts
    ```
  </Tab>
</Tabs>

**Generating `known_hosts`**

```shell
ssh-keyscan github.com > known_hosts
ssh-keyscan gitlab.com >> known_hosts
```

## tls

Creates a Kubernetes `Secret` of type `kubernetes.io/tls` containing TLS client certificates, private keys, and/or a CA certificate. Used for mTLS authentication with container registries, Helm repositories, or Bucket sources.

**Flags**

| Flag | Description |
|---|---|
| `--tls-crt-file` | Path to TLS client certificate file |
| `--tls-key-file` | Path to TLS client private key file |
| `--ca-crt-file` | Path to CA certificate file (optional) |

**Examples**

<Tabs>
  <Tab title="Full mTLS">
    ```shell
    flux-operator -n flux-system create secret tls registry-tls \
      --tls-crt-file=./tls.crt \
      --tls-key-file=./tls.key \
      --ca-crt-file=./ca.crt
    ```
  </Tab>
  <Tab title="CA Only (self-signed)">
    ```shell
    flux-operator -n flux-system create secret tls registry-ca \
      --ca-crt-file=./ca.crt
    ```
  </Tab>
  <Tab title="Export to YAML">
    ```shell
    flux-operator -n flux-system create secret tls registry-tls \
      --tls-crt-file=./tls.crt \
      --tls-key-file=./tls.key \
      --ca-crt-file=./ca.crt \
      --export
    ```
  </Tab>
</Tabs>

**When to use:** `FluxInstance` sync with `spec.sync.kind: OCIRepository` connecting to a registry with a self-signed certificate or requiring mutual TLS. Reference the secret via a kustomize patch on the `OCIRepository`:

```yaml
spec:
  kustomize:
    patches:
      - patch: |
          - op: add
            path: /spec/certSecretRef
            value: registry-tls
        target:
          kind: OCIRepository
```

<Tip>
  If the container registry uses a self-signed certificate but does not require client authentication, omit `--tls-crt-file` and `--tls-key-file` and provide only `--ca-crt-file`.
</Tip>

## web-config

Creates a Kubernetes Secret containing the Flux Web UI configuration, including OIDC provider settings for single sign-on.

**Flags**

| Flag | Description |
|---|---|
| `--base-url` | External URL for the Flux Web UI **(required)** |
| `--provider` | Authentication provider (default: `OIDC`) |
| `--issuer-url` | OIDC issuer URL **(required for OIDC)** |
| `--client-id` | OIDC client ID **(required for OIDC)** |
| `--client-secret` | OIDC client secret |
| `--client-secret-stdin` | Read the client secret from stdin |
| `--client-secret-rnd` | Generate a random client secret |

**Examples**

<Tabs>
  <Tab title="OIDC (stdin)">
    ```shell
    echo $OIDC_CLIENT_SECRET | flux-operator create secret web-config flux-web \
      --namespace=flux-system \
      --base-url=https://flux.my-org.com \
      --issuer-url=https://sso.my-org.com \
      --client-id=flux-web \
      --client-secret-stdin
    ```
  </Tab>
  <Tab title="OIDC (random secret)">
    ```shell
    flux-operator create secret web-config flux-web \
      --namespace=flux-system \
      --base-url=https://flux.my-org.com \
      --issuer-url=https://accounts.google.com \
      --client-id=my-client-id \
      --client-secret-rnd
    ```
  </Tab>
  <Tab title="Export to YAML">
    ```shell
    echo $OIDC_SECRET | flux-operator create secret web-config flux-web \
      --namespace=flux-system \
      --base-url=https://flux.my-org.com \
      --issuer-url=https://sso.my-org.com \
      --client-id=flux-web \
      --client-secret-stdin \
      --export
    ```
  </Tab>
</Tabs>

## webauth

Creates a Kubernetes Secret for Flux Web UI authentication. Use this sub-command for web authentication configurations beyond standard OIDC.

```shell
flux-operator create secret webauth my-webauth \
  --namespace=flux-system \
  --export
```

## Summary

| Sub-command | Secret Type | Primary Use Case |
|---|---|---|
| `basic-auth` | Opaque | Private Git or Helm repositories |
| `githubapp` | Opaque | GitHub App auth for `GitRepository` |
| `proxy` | Opaque | HTTP/S proxy with optional credentials |
| `registry` | `dockerconfigjson` | Private OCI / container registries |
| `sops` | Opaque | SOPS Age or GPG decryption keys |
| `ssh` | Opaque | SSH Git repository authentication |
| `tls` | `kubernetes.io/tls` | mTLS for registries and Helm repos |
| `web-config` | Opaque | Flux Web UI OIDC configuration |
| `webauth` | Opaque | Flux Web UI authentication |
