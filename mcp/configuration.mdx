The `flux-operator-mcp serve` command accepts flags that control how the server communicates with AI clients, what cluster permissions it enforces, and whether write operations are permitted. This page covers every configuration option with working examples for each scenario.

## Configuration Flags

| Flag | Description | Default |
|---|---|---|
| `--transport` | Transport protocol: `stdio`, `sse`, or `http` | `stdio` |
| `--port` | Port to listen on (for `sse` or `http` transports) | `8080` |
| `--read-only` | Run in read-only mode — disables all write tools | `false` |
| `--mask-secrets` | Mask sensitive values in Kubernetes Secrets | `true` |
| `--kube-as` | Kubernetes service account to impersonate | none |

## Transport Modes

### Standard Input/Output (`stdio`)

The default transport mode. The AI assistant spawns the MCP server as a subprocess and communicates over stdin/stdout. This is compatible with all supported clients and requires no network configuration.

```json
{
  "flux-operator-mcp": {
    "command": "/path/to/flux-operator-mcp",
    "args": ["serve"],
    "env": {
      "KUBECONFIG": "/path/to/.kube/config"
    }
  }
}
```

### Streamable HTTP (`http`)

The recommended web-based transport. Start the server manually and configure your AI client to connect to it over HTTP:

```shell
export KUBECONFIG=$HOME/.kube/config
flux-operator-mcp serve --transport http --port 8080
```

Connect your AI assistant to the running server:

```json
{
  "mcp": {
    "servers": {
      "flux-operator-mcp": {
        "type": "http",
        "url": "http://localhost:8080/mcp"
      }
    }
  }
}
```

### Server-Sent Events (`sse`)

A legacy web-based transport, superseded by Streamable HTTP in the MCP specification. Use this only for clients that do not yet support the `http` transport.

```shell
export KUBECONFIG=$HOME/.kube/config
flux-operator-mcp serve --transport sse --port 8080
```

```json
{
  "mcp": {
    "servers": {
      "flux-operator-mcp": {
        "type": "sse",
        "url": "http://localhost:8080/sse"
      }
    }
  }
}
```

## Security Options

### Read-Only Mode

Restrict the server to reporting and documentation tools only. All tools that modify cluster state — `reconcile_*`, `suspend_flux_reconciliation`, `resume_flux_reconciliation`, `apply_kubernetes_manifest`, `delete_kubernetes_resource`, and `install_flux_instance` — are disabled.

```json
{
  "flux-operator-mcp": {
    "command": "/path/to/flux-operator-mcp",
    "args": [
      "serve",
      "--read-only"
    ],
    "env": {
      "KUBECONFIG": "/path/to/.kube/config"
    }
  }
}
```

<Warning>
  It is strongly recommended to run the in-cluster Kubernetes deployment with `--read-only` in
  production environments to prevent the AI assistant from inadvertently modifying cluster state.
</Warning>

### Secret Masking

By default, sensitive values in Kubernetes Secrets are masked before being returned to the AI assistant. This prevents credentials from appearing in chat history or model context. Secret masking is enabled by default and can be explicitly disabled:

```json
{
  "flux-operator-mcp": {
    "command": "/path/to/flux-operator-mcp",
    "args": [
      "serve",
      "--mask-secrets=false"
    ],
    "env": {
      "KUBECONFIG": "/path/to/.kube/config"
    }
  }
}
```

<Warning>
  Disabling secret masking exposes sensitive values to the AI assistant and potentially to its
  training data. Only disable this in controlled environments when using self-hosted models
  where data retention is fully under your control.
</Warning>

### Service Account Impersonation

Limit the server's Kubernetes permissions to those granted to a specific service account. This is useful for enforcing least-privilege access in shared or production environments:

```json
{
  "flux-operator-mcp": {
    "command": "/path/to/flux-operator-mcp",
    "args": [
      "serve",
      "--kube-as=system:serviceaccount:my-namespace:my-service-account"
    ],
    "env": {
      "KUBECONFIG": "/path/to/.kube/config"
    }
  }
}
```

<Note>
  The user configured in your kubeconfig must have the `impersonate` verb for service accounts in the target namespace. Verify with `kubectl auth can-i impersonate serviceaccount -n my-namespace`.
</Note>

## Kubernetes In-Cluster Deployment

Deploy the MCP server as a managed workload on your cluster using a Flux `ResourceSet` and `HelmRelease`. The Helm chart is published to `oci://ghcr.io/controlplaneio-fluxcd/charts/flux-operator-mcp`.

```yaml
apiVersion: fluxcd.controlplane.io/v1
kind: ResourceSet
metadata:
  name: flux-operator-mcp
  namespace: flux-system
spec:
  inputs:
    - readonly: false
      accessFrom: flux-system
  resources:
    - apiVersion: source.toolkit.fluxcd.io/v1
      kind: OCIRepository
      metadata:
        name: << inputs.provider.name >>
        namespace: << inputs.provider.namespace >>
      spec:
        interval: 60m
        url: oci://ghcr.io/controlplaneio-fluxcd/charts/flux-operator-mcp
        layerSelector:
          mediaType: "application/vnd.cncf.helm.chart.content.v1.tar+gzip"
          operation: copy
        ref:
          semver: "*"
    - apiVersion: helm.toolkit.fluxcd.io/v2
      kind: HelmRelease
      metadata:
        name: << inputs.provider.name >>
        namespace: << inputs.provider.namespace >>
      spec:
        serviceAccountName: flux-operator
        chartRef:
          kind: OCIRepository
          name: << inputs.provider.name >>
        interval: 30m
        values:
          transport: http
          readonly: << inputs.readonly >>
          networkPolicy:
            ingress:
              namespaces: [<< inputs.accessFrom >>]
```

Key deployment notes:

- The server runs with `cluster-admin` permissions via the `flux-operator` service account
- The `readonly` input maps to the `--read-only` flag; set it to `true` for production
- The `accessFrom` input controls which namespaces can reach the server via NetworkPolicy
- The server listens on port `9090` inside the cluster

### Connecting to the In-Cluster Server

Start a port-forward session from your local machine:

```shell
kubectl port-forward -n flux-system svc/flux-operator-mcp 9090:9090
```

Then configure your AI assistant to connect via HTTP:

```json
{
  "mcp": {
    "servers": {
      "flux-operator-mcp": {
        "type": "http",
        "url": "http://localhost:9090/mcp"
      }
    }
  }
}
```

For clients that only support the legacy SSE transport:

```json
{
  "mcp": {
    "servers": {
      "flux-operator-mcp": {
        "type": "sse",
        "url": "http://localhost:9090/sse"
      }
    }
  }
}
```

<Warning>
  When running in-cluster, kubeconfig context switching tools (`get_kubeconfig_contexts` and
  `set_kubeconfig_context`) are disabled — the server can only access the cluster it is deployed
  in. To compare deployments across multiple clusters, deploy the MCP server in each cluster and
  configure each instance separately in your AI assistant.
</Warning>

For the full Helm chart values API, see the [flux-operator-mcp chart documentation](https://github.com/controlplaneio-fluxcd/charts/tree/main/charts/flux-operator-mcp).
